# Release v0.4.0-beta — Fresh Install Impecable + Ecosistema

> Fecha: 2026-08-15 · Predecesor: v0.3.8-alpha (d8eabcc) · Ramas fusionadas: `feature/unified-memory-v0.3.9`

## Resumen ejecutivo

Release consolidado del plan de mejora 2026-08. El framework pasa de "prototipo con memoria rota" a
"funcional out-of-the-box": primer arranque sin errores, memoria dual (SQLite + Markdown) unificada,
ecosistema de skills/agentes consistente y ruta de actualización validada E2E.

**Sin breaking changes de API.** Los datos del usuario se preservan al actualizar desde v0.3.8.

## Qué cambia para el usuario

| Antes (v0.3.8) | Ahora (v0.4.0-beta) |
|---|---|
| Fresh install: 3 errores + 4 warnings | Primer arranque: **0 errores** (auto-heal) |
| `session_search "X"` no veía mensajes capturados | Búsqueda unificada MD + SQLite |
| Knowledge extraction "OK" sin extraer nada (false-green) | Extracción real desde ambas fuentes |
| "Recuerda que..." no persistía | Facts automáticos en `user_facts` |
| Dashboard mostraba 0 sesiones con fecha falsa | Memoria unificada + fecha real |
| Docs referenciaban ~10 scripts inexistentes | Doc-drift cero (54 scripts reales verificados) |
| context-scout duplicado (v2 huérfana) | Agente único fusionado |
| catalog.json con 15/23 skills | Catálogo 23/23 sincronizado |
| backlog.md creado como `{}` por migrate.py | Seed markdown correcto + CRUD funcional |

## Cómo actualizar desde v0.3.8

```bash
python core/scripts/update.py          # detecta nueva versión, preserva contexto
python core/scripts/system_check.py    # verificar salud post-update
```

Datos preservados automáticamente: `workspaces/`, `core/.context/` (MASTER.md, profile.md,
sessions, codebase, backups, projects, vitals, knowledge/insights, learning), `sessions/`, `logs/`.

## Detalle técnico por fase

### Fase 1 — Memoria unificada
- `session_search.py`: fuente unificada `SESSIONS_DB` + MD, auto-index de sesiones markdown
  faltantes, dedup por session_id, `unified_search: true` en `config/framework.yaml` (rollback disponible).
- `knowledge_extractor.py`: adapter `SQLiteSessionContent` (duck-typed) + `extract_from_session_id`
  + CLI (`--source sqlite|markdown`, `--session-id`, `--user`, `--output-json`, `--list-sessions`).
  Corrige el false-green de `memory_pipeline` (invocaba un script sin CLI).
- `message_hook.py`: regex de facts ("Recuerda que.../Remember that.../No olvides que...")
  → `set_user_fact(category="user_preference")`.
- `system_check.py --fix`: crea MASTER.md/profile.md desde templates.
- `generate_dashboard_data.py`: usa la búsqueda unificada; `generatedAt` real.

### Fase 2 — Fresh install
- `session_start.py`: auto-heal de primer arranque vía `system_check --fix --quiet-first-run`.
- Doc-drift: 17 archivos corregidos. Renames con guion → underscore, `framework-guardian.py`
  (inexistente) → `system_check.py`, launcher del dashboard → `python -m http.server`,
  propagación legacy → `update.py`.
- Versiones sincronizadas vía `version_updater.py` (gap de AGENTS.md corregido manualmente).

### Fase 3 — Ecosistema
- `context-scout.md` absorbe la detección multi-señal de `context-scout-v2.md` (huérfana).
- `catalog.json`: +8 skills → 23/23.
- `migrate.py`: los `.md` ya no se crean como JSON; usan `*.seed.md` si existen.
- `backlog.seed.md` + auto-fix → `backlog_manager.py` CRUD funciona desde fresh install.

### Fase 4 — Release
- Version bump coordinado vía `version_updater.py` en 6 archivos + VERSION + AGENTS.md + CHANGELOG.
- Este archivo.
