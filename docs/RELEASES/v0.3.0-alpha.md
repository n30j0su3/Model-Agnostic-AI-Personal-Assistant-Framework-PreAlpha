## Executive Summary

The CORE Redesign (Phases 1–3) represents a fundamental restructuring of the PA
Framework's initialization, error handling, and knowledge management subsystems.
The redesign achieved a **92% reduction in initialization time** (58s → 4.58s),
introduced a **lazy tier-based context loading system** (ADR-001), a
**taxonomy-driven recovery engine** (ADR-004), and a **cross-session pattern
detection** pipeline. All changes maintain the framework's model-agnostic design
principle — no provider-specific dependencies.

## Architecture Changes

### 1. Tier-Based Context Loading (ADR-001)

The `ContextLoader` implements a 5-tier lazy loading strategy:

| Tier | Name | Content | Loading | Token Budget |
|------|------|---------|---------|--------------|
| 0 | Bootstrap | AGENTS-lite.md | Immediate | 500 |
| 1 | Essential | MASTER.md, session index, profile | Immediate | 1,000 |
| 2 | Context | Recent sessions, playbooks summary | **Lazy** | 2,000 |
| 3 | Reference | Templates, quick-start, navigation | **Lazy** | 5,000 |
| 4 | Historical | Archive sessions, backups index | **Lazy** | 10,000 |

- Tiers 0–1 load at startup (essential for any operation).
- Tiers 2–4 are deferred and loaded only when accessed.
- `TokenBudgetTracker` enforces per-tier token limits with automatic truncation.
- `parallel_load_tiers()` enables concurrent loading of multiple tiers.

### 2. Recovery Orchestrator (ADR-004)

The `core/recovery/` package implements a self-healing engine:

- **Triggers** (`triggers.py`): Maps Python exceptions to 7 ADR-004 taxonomy
  categories via `TAXONOMY_MAP` (exact match) and `KEYWORD_PATTERNS` (fuzzy
  match). Includes `should_trigger_recovery()` gate that skips trivial errors
  (KeyboardInterrupt, SyntaxError, etc.).

- **Orchestrator** (`orchestrator.py`): End-to-end recovery pipeline:
  `classify → match → execute`. Maps taxonomy categories to playbook IDs
  via `CATEGORY_TO_PLAYBOOKS`. Maintains execution history for diagnostics.

- **Built-in Actions**: 8 recovery actions (PB-001 through PB-008) covering
  encoding, file-not-found, JSON parsing, subprocess timeout, path resolution,
  YAML parsing, git sync, and multi-CLI conflicts.

### 3. Pattern Detection Pipeline

The `PatternDetector` (`knowledge-pattern-detector.py`) provides built-in recovery actions.

### 3. Pattern Detection Pipeline

The `PatternDetector` analyzes cross-session data to identify:

- Recurring error patterns and their frequency
- Common themes and topics across sessions
- Knowledge extraction candidates
- Trend analysis for proactive issue detection

## ADR-004 Error Taxonomy

The recovery system classifies errors into 7 categories:

| Category | Example Exceptions | Mapped Playbooks |
|----------|--------------------|------------------|
| `network` | ConnectionError, TimeoutError, BrokenPipeError | PB-004 |
| `api` | HTTPError, RateLimitError | PB-004 |
| `file_system` | FileNotFoundError, PermissionError, OSError | PB-002, PB-005 |
| `authentication` | UnauthorizedError, TokenExpiredError | *(none yet)* |
| `configuration` | ConfigParserError, EnvironmentError | PB-006 |
| `data_integrity` | UnicodeEncodeError, JSONDecodeError, ValueError | PB-001, PB-003 |
| `resource` | MemoryError, SubprocessError, ImportError | PB-004 |

## Migration Notes (v0.2.x → v0.3.0-alpha)

### Breaking Changes

1. **session-start.py API**: Now uses `ContextLoader` internally. The
   `run_parallel_checks()` function returns a different structure that
   includes tier loading metadata. Any code directly parsing the old
   output format will need updating.

2. **error_logger.py**: Error log entries now include additional fields:
   `taxonomy_category`, `recovery_suggestion`, and `playbook_id`. Existing
   log consumers should handle these new fields gracefully (they are
   optional/additive).

3. **knowledge-extractor.py**: Refactored to delegate parsing to
   `PatternDetector`. The `extract_all_knowledge()` return format is
   backward-compatible, but internal class structure has changed.

### New Dependencies

- `core/recovery/` package must be importable from `core/scripts/` working
  directory.
- `knowledge-pattern-detector.py` must be in the same directory as
  `knowledge-extractor.py`.

### Configuration Changes

- No changes to `config/framework.yaml` or user-facing configuration.
- New `AGENTS-lite.md` file at project root (Tier 0 bootstrap).
- Existing `AGENTS.md` continues to work as the full documentation entry point.

### Upgrade Path

1. Update all files (framework sync or manual copy).
2. Verify `core/recovery/__init__.py`, `orchestrator.py`, and `triggers.py`
   are present.
3. Verify `core/scripts/context_loader.py` and
   `core/scripts/knowledge-pattern-detector.py` are present.
4. Run `python core/scripts/session-start.py` — should complete in <5s.
5. Run `pytest core/scripts/tests/` — should show 208 passed, 1 skipped.
